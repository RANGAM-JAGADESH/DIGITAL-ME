## SECTION 3: PROJECTS AND PRACTICAL EXPERIENCE

### Q15. Explain your TripMate AI project.

A: TripMate AI is a multi-agent AI travel planning application. The idea is to help users plan trips by organizing different travel-related tasks through AI agents. I also learned why error handling and structured responses are important when integrating external services.

### Q17. Tell me about your Webhook Payment Simulator.

A: I developed a Webhook Payment Simulator to understand how payment systems communicate between independent applications. It contains two applications: FakePay, which simulates a payment service, and MyShop, which represents a merchant application. I used FastAPI to develop the services and implemented webhook communication using HMAC-SHA256 signature verification. The project helped me understand payment notifications, request verification, and why a merchant should not blindly trust incoming webhook requests.

### Q18. Why did you build a Webhook Payment Simulator?

A: I wanted to understand what happens behind the scenes when an online payment is processed. For example, sometimes a customer sees money deducted from their bank account, but the merchant doesn't receive a successful payment confirmation. I wanted to explore how independent systems communicate, how payment status updates happen, and how duplicate webhook events should be handled. Building this simulator gave me a practical way to understand these concepts instead of learning only from theoretical explanations.

### Q19. What is HMAC-SHA256, and why did you use it?

A: HMAC-SHA256 is a message authentication mechanism that uses a secret key and the SHA-256 hash function to generate a signature. In my Webhook Payment Simulator, I used it to verify that incoming webhook requests were generated by a party that knows the shared secret and that the message hasn't been modified. The receiver recalculates the signature using the raw request body and compares it with the received signature using a timing-safe comparison. This helps protect webhook communication from unauthorized or modified requests.

### Q23. What is RAG?

A: RAG stands for Retrieval-Augmented Generation. It is a technique where an application retrieves relevant information from an external knowledge source and provides that information to an LLM before generating a response. For example, if I upload my resume and someone asks about my technical projects, the system retrieves the relevant information from my documents and passes it to the LLM. This helps the model generate answers based on my actual information rather than relying only on its pre-trained knowledge.

### Q24. What is the difference between RAG and Agentic RAG?

A: In traditional RAG, the system generally follows a predefined process of retrieving relevant information and passing it to the LLM. Agentic RAG introduces an additional decision-making layer where an AI agent can decide whether retrieval is necessary, which source to search, whether the retrieved information is sufficient, and whether another retrieval attempt is required. I'm particularly interested in Agentic RAG because it introduces more flexible reasoning and workflow orchestration.

### Q25. What is LangGraph, and why did you use it?

A: LangGraph is a framework for building stateful and multi-step AI workflows. I explored it because I wanted to understand how multiple AI tasks can be organized into a structured execution process. In my TripMate AI project, I used it to organize different stages of the application. I find concepts such as nodes, edges, state management, conditional routing, and workflow execution particularly interesting.

### Q26. What is an AI agent?

A: An AI agent is a system that can receive a goal, make decisions about the steps required, and use available tools to perform tasks. For example, in a travel planning application, an agent might retrieve flight information, another might search for hotels, and another might organize destinations into an itinerary. The important concept is that an agent doesn't only generate text; it can also interact with tools and services to complete a task.

### Q27. What is your understanding of LLMs?

A: Large Language Models are machine learning models trained on large amounts of text to understand and generate language. They process input using tokens and generate output based on learned patterns and model parameters. I've been exploring concepts such as transformers, attention mechanisms, embeddings, tokenization, logits, temperature, and sampling. I want to understand not only how to call an LLM through an API but also what happens internally when the model generates a response.

### Q28. Are you currently exploring any new AI technologies?

A: Yes, I'm continuously exploring technologies related to AI engineering. Currently, I'm particularly interested in RAG applications, LangChain, LangGraph, LLM architectures, embeddings, vector databases, and AI agents. I also want to understand how to develop and deploy intermediate-level AI applications using free and open-source technologies. My learning approach is to understand the concepts first and then implement them in practical projects.
